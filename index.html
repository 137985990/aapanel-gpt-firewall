功能指南

按范围配置、按证据调整，避免把局部问题扩大为整站误封。

01 / 基础防护

“站点”管理站点开关、常规规则、URI 规则与可信代理；“全局”影响多个站点。CC 为固定阈值限流与增强限流，不是动态智能 CC，也不提供可信机器人验证。

02 / 接口策略

选择站点 → 新建并保存停用规则 → 勾选启用、保持观察并保存 → 手动查看证据 → 必要时改为拒绝或限域封禁。观察只记录，不放行或绕过原有规则；现有显式白名单仍优先。

03 / 核对与排障

“统计”与“日志”辅助排障，注意采样和覆盖说明；安全巡检需手动运行。“更新”仅检查，不会自动安装。当前不提供 JSON 请求体检测；不要用全局白名单替代精确规则调整。

全局规则

站点没有单独覆盖时，会继承这里的全局默认规则。

在一个基础视图中检查规则状态、响应码和可编辑规则集。
  • 继承：全局设置会自动作为默认值被站点配置所继承
  • 规则优先级参考：IP白名单 > IP黑名单 > UA白名单 > UA黑名单 > URL关键字拦截 > URL CC防御 > URL白名单 > URL黑名单 > 非浏览器 > User-Agent > CC防御 > Cookie > URI过滤 > URL参数 > POST > 站点自定义防御。
  • 以上是功能参考顺序，并非实际执行链；GPT Firewall 部分控制项尚未实现，界面列出不代表已启用防护，请以实际配置和检查结果为准。

防护行为以当前配置和巡检结果为准。请先核对本站点的规则覆盖和 CC 防御配置，再决定是否修改。

规则覆盖

禁用当前站点上的某条全局规则，用于处理单站点误报。

  • 开关只影响当前站点；不会删除或修改全局规则。
  • 全局已停用的规则在站点侧不会生效，建议先在全局页面确认规则状态。

站点URL白名单

只放行当前站点的指定 URL 规则，用于处理单站点误报，不会写入全局白名单。

  • 站点URL白名单优先用于误报处理，不影响其他站点。
  • 建议使用精确前缀，不要写覆盖整站的宽泛规则。

URI自定义拦截

站点级 URI 自定义拦截规则。只添加已确认的恶意路径，匹配后会直接拦截。

  • 手动处理：本页不会从日志自动创建规则。
  • 确认误报优先使用 URL 白名单；自定义拦截只用于确认的攻击路径。

URI加密保护

要求受保护 URI 携带指定参数口令，仅用于后台、下载等敏感入口。

  • 这是站点级 URI 加密保护规则，配置过宽会拦截正常流量。
  • 除非客户端一定会携带参数口令，否则不要用于 API 或自动化客户端入口。

CDN请求头管理

管理本站点可信的客户端 IP 请求头。只有站点确实在可信代理或 CDN 后面时才启用。

可信代理来源

配置后只信任这些代理或 CDN 来源 IP 段传入的客户端 IP 请求头；留空时保持旧版兼容行为。

  • CDN请求头只影响真实客户端 IP 的读取方式，不会添加黑名单。
  • 不要信任公网可伪造的请求头，除非 CDN 会清理客户端自带的同名头。
  • 建议填写 CDN 或反向代理的出口 IP 段，避免客户端伪造转发头。

黑名单

管理拒绝访问的 IP 段、URL、User-Agent、Header、Cookie、GET 和 POST 规则。

单 IP 规则可作为临时封禁；IP 段规则会持续生效，除非进入白名单。
IP黑名单 URL黑名单 UA黑名单 Header黑名单 Cookie黑名单 GET参数黑名单 POST黑名单
  • 封禁时长仅单 IP 生效，可选 5 分钟到 10 年；IP 段规则长期生效。
  • 这里的 IP 段会被拒绝访问，除非已经加入 IP 白名单。
  • URL黑名单会拦截匹配路径；URL白名单和IP白名单优先级更高。
  • 建议只拦截明确的后台、扫描路径，不要写过宽规则。
  • UA黑名单用于明确恶意客户端；empty_ua 仍全局忽略，不在这里封禁。
  • API 或自动化客户端建议优先加入 UA 白名单或 URL 白名单，不要写宽泛 UA 黑名单。
  • Header黑名单会匹配请求头名称和值；规则过宽容易误伤正常浏览器和 API 客户端。
  • 建议只拦截非常明确的恶意头，例如特定扫描器、异常代理头或攻击特征。
  • Cookie黑名单会匹配 Cookie 内容；规则过宽会误伤登录、会话和统计参数。
  • 建议只拦截明确攻击特征，不要把普通 token、session、uuid 写入黑名单。
  • GET参数黑名单会匹配 URL query 参数；规则过宽会误伤正常搜索、分页和 API 参数。
  • 建议只拦截明确攻击特征，不要把普通业务参数名写成宽泛正则。
  • POST黑名单会匹配请求体内容；规则过宽可能影响表单提交、登录和 JSON API。
  • 新增 POST 规则前建议先在日志或报表中确认误报范围。

白名单

管理可信 IP 段、URL 和 UA 规则，用于绕过大部分 WAF 检查。

空 User-Agent 的处理以当前配置和巡检结果为准。URL 白名单请在确认误报后人工维护，注意全局规则的影响范围。
IP白名单 URL白名单 UA白名单
  • 加入IP白名单的IP段，所有拦截规则均对其失效。
  • 单IP请在起始IP和结束IP中填写相同地址。
  • 加入URL白名单的路径，大多数拦截规则均对其失效（CC防御除外）。
  • 支持正则表达式，例如：^/api/upload
  • UA白名单优先于UA黑名单，可用于放行明确可信的 API 或自动化客户端。
  • 不要把未知公网 UA 大范围加入白名单；API 路径仍建议配合 URL 白名单。
