# 更新管理

## 从哪个版本开始支持

社区更新入口从 v0.1.1 开始提供。当前项目版本为 v0.1.9，仍为实验性兼容预发布；核验发布记录与来源后，已核验的 v0.1.1 至 v0.1.8 用户可使用现有入口确认升级。旧 v0.1 无此功能，须按 [升级教程](UPGRADE.md) 手动上传已核验的 v0.1.9 升级包，不必先装 v0.1.1，也不能靠没有安装的更新器自动升级自身。内部插件名仍为 `free_waf`，不另装第二个插件。

## v0.1.9 国内兼容与商城边界

国内第三方 `free_waf 8.4`（原作者 **明国三年一场雨**）兼容从 v0.1.9 提供。`8.4` 是插件版本，实测面板版本为 `12.0.0`。历史 v0.1.8 的标签、附件与摘要保留，不包含本次兼容；已有 v0.1.8 用户检查并确认安装 v0.1.9，不通过覆盖同版本实现升级。发布不自动更新生产服务器。

实际仅验证宝塔面板 `12.0.0`、Python `3.7.16`、宝塔 Nginx `1.28.3`、Debian `12` 的临时机：原版 8.4 → GPT → 还原 8.4 → GPT 已完成，两条受测拦截路径 403、正常请求 200、JSON POST 200。只证明这一矩阵和受测请求，不证明 JSON 检测完整、其他平台或生产适用。

安装器按严格 Lua SHA256 指纹识别已核验国内原版与已知社区版，未知／自定义／付费来源默认拒绝；纯 aaPanel 5.0 原始指纹尚未验证，不能仅凭完整目录或版本号宣称支持。原版的显式字段补齐、仅三个缺失规则空表、JSON／上传／蜘蛛 PTR／算术挑战差异及缺字段、无明确到期单 IP 封禁、异常索引拒绝条件，统一见 [国内 8.4 迁移边界](UPGRADE.md#国内-84-迁移边界)。

商城可能仍显示原插件旧名，或把上游 `8.4` 当作高于社区 `0.1.9` 而提示“更新”。**不要点击旧商城更新，也不要开启其自动更新覆盖 GPT。** 两者不是同一版本序列；社区后续更新走“维护工具 → 插件更新”的 GPT 更新器，核验具体发布附件，不改商店身份或版本号欺骗比较。

## 包兼容约定

v0.1.9 运行 ZIP **严格保持 v0.1.1 的 21 个受管文件集合不变**，旧更新器不需要放宽文件白名单就能校验新包。访客地域、接口策略移除、重复封禁和安全边界的回归测试，以及 Lua 审计脚本、统计／任务管理画廊图片和根目录 `AGENTS.md` 只进入源码快照；总览截图仍在原受管集合中，完整 Agent 执行清单随包保留在 `docs/UPGRADE.md`。`docs/plans/` 为私有工作资料，不加入公开提交、源码快照或发布包。实际站点的 `repeat_bans.json` 是独立运行数据，不加入升级包，也不覆盖。不要把源码包当安装包，也不要为显示画廊或补依赖绕过校验。

更新入口位于“维护工具 → 插件更新”。首页区分配置开关与接入状态，打开插件不自动核验 Nginx。手动核验不写入或重载；非受管入口仅有磁盘配置证据，本版受管入口还会尝试本机 Lua 健康验证，但均不代表所有站点受保护。

## v0.1.8 只读访客地域

“观测分析 → 网站统计 → 访客地域”沿用所选站点、时间范围与后台报告缓存，增加世界分布图、国家／省／城市排行、国家趋势和活跃自然日 `active_days`。默认按独立 IP 展示，可切换请求数与响应体字节；包含机器人和 API 请求，不代表人数、真人或停留时长。统计采用现有日志实际记录的地址，CDN／代理后可能只是出口，不推断 XFF、不改可信代理或日志格式。

分类覆盖已处理样本中的全部计数 IP，不限客户端 Top 50；国家保留全部已分配代码的定位结果。只读固定面板本地 MMDB，兼容标准／定制字段与 IPv6；私有、未知、缺库、失败和定位预算耗尽有明确提示。单报告最多查询 10000 个独立公网 IP，协作式时间预算 1.5 秒；日志部分扫描和地域部分定位分别报告，不能把样本内计数当作整段所选期间的全量计数。省／地区最多 200 项、城市最多 500 项，主要按独立 IP 排序截取；切换指标不恢复省略分组。

地图资源仅在进入地域页后按需从面板本地加载；封禁 IP 归属地复用缓存的本地攻击地域查询，不新增联网定位、依赖安装、遥测或 JS 跟踪组件，不改 WAF 规则。顶层报告 schema 2 新增 geography schema 1，后台缓存键前缀改为 `website-statistics-v3-geography`；升级后重新打开插件并生成报告，不清空日志。旧截图不代表新增页面，说明不表示已经发布或部署。详情见 [README](../README.md#v018-访客地域统计)。

## v0.1.8 发布与恢复保护

新更新执行器在核验、暂存、备份、代码替换、安装、回退和最终状态写入期间共用安装生命周期锁。嵌套离线安装必须匹配任务身份、直接父进程及继承的锁文件描述符；非锁主不覆盖 `install-status.json`。发布前核对预期文件，恢复时核对同一打开文件的身份和摘要，并核验备份；发现人工变更时保留并报告冲突，不强行覆盖。

锁改进不可能追溯修复已经运行的旧版更新进程。首次从旧版本升到本版时仍须先做独立备份、暂停所有并发安装／接入修复与配置编辑；新包继续兼容旧版 21 文件校验，不代表旧执行器因此获得所有新增保护。不通过删除锁、修改任务状态或关闭摘要验证解决更新失败。

首次原版升级尤其如此：原管理器不遵守新锁，必须在上传前暂停规则／站点／名单等管理写操作并独立备份。国内兼容迁移的私有 `compatibility-migration.json` journal 未完成，或预检、激活、回退发现同期变化时停止；不自动覆盖新值，不删 journal 后重试，先对照本次备份和实际文件人工处理。

规则发布另有 `.policy-recovery/pending.json` 私有恢复记录，位于 WAF 运行目录，内含本次原始与候选配置。若存在，先停止管理写入，核对实际文件及同期待保留的人工变更；不能上传该记录，也不能只删除它恢复按钮。它不是受管代码，代码升级或回退不清除该记录。统计异步落盘、日志部分覆盖与剩余边界见 [安全说明](../SECURITY.md)。

## v0.1.7 可选重复封禁升级

入口为“防护配置 → 重复封禁升级”，按需读取站点并由管理员明确选择，不在插件首屏或后台持续查询。策略保存在 `site.json` 每站点的 `repeat_ban_policy`，默认 `enabled=false`，字段缺失等同于停用；升级不自动创建或启用策略，也不改已有接口规则。默认滚动 86400 秒（24 小时），5 次独立自动封禁对应 604800 秒（7 天），10 次对应 2592000 秒（30 天）。支持 1 至 8 档，窗口 60 至 604800 秒、次数 2 至 1000、时长 60 至 31536000 秒，均为整数，各档次数和时长须严格递增。

只计同一站点、同一 IP 独立且成功建立的自动封禁；普通命中、人工封禁、观察／仅拒绝动作、已封禁期间的重复访问不计，不因重试自动升级或续期。IP 白名单优先，升级不影响其他站点，但会覆盖所选站点整个站点；接口来源也会扩为本站点整站封禁，必须单独确认启用。共享 NAT 或代理可能扩大误封范围，先在隔离环境核对，不能把更新代码当作开启授权。

默认“解除（保留计数）”发送 `reset_counts:'0'`，保留有效滚动历史，提前解封后再次独立自动封禁继续累计；“解封并清零”才发送 `reset_counts:'1'` 并清零相应计数。这两种站点操作均需明确确认，都不清除独立人工／基础封禁。原有按 IP 的全局单独解封（`remove_btwaf_drop_ip`／`remove_drop_ip`）跨站移除该 IP 的升级记录，但保留有效滚动历史；全局入口中，只有 `clean_btwaf_drop_ip` 的“全部清理”才重置所有重复封禁历史。默认 7 天自然到期时，原 24 小时计数已过期；10 次档位可能经提前解封保留计数、并在窗口内再次独立违规达到，不靠封禁期间反复访问。

滚动历史仅在 Nginx 共享内存中，平滑重载（smooth reload）可保留，完全重启（full restart）后不恢复；计数压力、驱逐、写入失败或锁竞争可少计，不从日志补算。长封禁另存 `/www/server/free_waf/repeat_bans.json`，不是持久全局黑名单；停用策略后，保留记录不由本策略执行。

此可选功能仅在 Linux x86_64/AArch64 的 LuaJIT FFI 与本地文件锁可用时支持，不新增包依赖；FFI 不可用或锁失败时功能降级，不联网补装，其他环境保持原有防护，不保证重复封禁升级。共享内存修订提示不保证快照即时同步；缺少修订提示时，解封结果跨 worker 最长需 10 秒可见。详情和字段见 [README](../README.md#v017-重复封禁升级)。本说明不代表已经发布或完成生产验收，现有截图不变，不以旧图冒充新功能截图。

## 只读任务管理

v0.1.6 同时新增“维护工具 → 任务管理”：只读进程与网络，打开插件不采集任务，进入该页按需读取，后续手动刷新。它不改配置、不终止进程、不调用 Shell、不上传；详情与覆盖限制见 [使用说明](../README.md#v016-只读任务管理)。任务管理的实现保留在既有统计服务文件内，避免新文件被旧更新器拒绝，不为此放宽更新白名单。

## 手动一键修复接入

入口位于“维护工具 → 诊断工具”的最后一个“一键修复”标签。更新代码不等于授权修复，只有管理员预览本次条件并明确确认后才执行。

1. 先建立独立备份、保留 SSH 管理通道并检查现有已开启规则。完整运行目录、受支持的 HTTP 通配站点入口、无既有接入文件、无冲突 Lua 入口和空闲回环端口是必要条件。
2. 点击“一键修复”只读预检，查看已开启站点数。预览后配置发生变化必须重新预览，不能沿用旧确认；不从浏览器接收命令、文件路径或下载地址。
3. 确认后在插件私有 `data/updates/integration-backups` 保存配置快照与清单，独占创建固定接入文件，检查并平滑重载宝塔 Nginx；不改变原开关、名单、阈值或规则。
4. 使用仅绑定 `127.0.0.1:39091` 的受管健康入口，检查随机标识、版本及实际 TCP 连接所属 Nginx worker 和 master 的身份。验证进程超过 5 秒会被结束，无法验证不显示成功。不要向公网映射这个端口。
5. 成功仅证明本机探针执行 Lua，原有开启规则将开始处理请求。需另测正常登录、表单、API 和站点内覆盖；其他 `location` 自定义 access 处理器可能覆盖继承入口。

修复期间阻止同时运行安装或更新。重载前后核对预览配置及运行文件，检测到同期修改时停止，不重载未知变更。无法阻止不遵守本插件锁的 root 或其他程序在检查后的瞬间写文件，因此这不是跨进程原子事务；不要同时编辑 Nginx 或防火墙配置。

失败尝试将本次发布的接入文件移动到私有备份中，再校验并按需重载旧配置。被替换或修改的文件不删除；身份不符、配置变化或恢复失败记为 `recovery_required`，停止再次修复和更新，需管理员先核对 `data/updates/integration-repair.json` 与备份。不要删记录绕过保护。回退不恢复全部共享内存，重载信号不等于旧工作进程已完成恢复。

v0.1.3 修复没有 `free_waf.conf` 接入文件时的兼容升级：旧运行数据仍须完整，既有接入文件和 Nginx 生效配置仍须通过安全校验。未加载本插件时只升级代码，不创建接入配置、不重载 Nginx、不自动启用防护；界面明确提示未启用。不能用更新成功代替防护生效验收。

v0.1.9 已移除接口策略的页面、管理接口、事件查询和请求执行，不会自动添加或启用站点 `endpoint_limits`，不会改原防护阈值。历史配置和采样事件文件保留，不再由该模块执行或续写，也不纳入受管代码覆盖或代码回退。历史 v0.1.8 附件不变，只有完成明确授权的服务器升级后，运行行为才随之变化。

沿用 v0.1.2 对旧 `security_verification` 算术／JavaScript 挑战的替换：通用 429 JSON 与 `Retry-After` 不反射 URI、不建立 IP 验证绕过；旧 CC 按站点和不含查询串的规范化路径计数。管理员应在测试环境验证正常客户端重试，不把“配置未变”理解为所有运行行为完全不变。

## 自动检查，不自动安装

打开插件后延迟检查固定社区 GitHub 仓库，检查结果缓存 6 小时，不占用首屏加载；可在“维护工具 → 插件更新”手动刷新。关闭插件后不承诺按时定期检查，也不会自动下载或安装版本。

手动强制检查仍有最短 60 秒间隔，避免连续点击触发 GitHub 限流。在线升级包必须符合当前更新器的固定受管文件清单；未来若需要新增文件或依赖，会另行提供迁移说明，不能通过放开压缩包白名单强行安装。

仅识别已发布的合法数字版本，草稿不展示；预发布会明确提示。版本不是按字符串排序，v0.1 等价于 0.1.0；不会降级或重新安装相同版本。服务器无法连接 GitHub 或被限流时保留明确提示，现有防护继续运行，可改用离线升级。

正常分块响应可以读取。真实联网在独立短进程中进行，单次请求超过 10 秒时结束该进程并回收结果，覆盖 DNS、TLS、响应头和正文阶段，避免慢连接长期占用检查请求或更新锁；超时不会触发安装。进程创建、系统资源或强制结束本身仍受操作系统状态影响。

## 一键更新流程

1. 查看目标版本和更新说明，先保留独立备份与管理通道；备份运行目录时确认包含 `site.json` 和存在的 `repeat_bans.json`，不能用受管代码备份代替运行数据备份。
2. 点击一键更新并确认。浏览器仅提交目标版本号，不提交自定义下载地址或安装命令。
3. 后台重新核对发布记录，下载固定来源附件，验证 SHA256SUMS 和存在时的 GitHub 附件摘要，检查 ZIP 路径、大小、重复项、链接、受管文件白名单与版本。
4. 先备份受管插件代码和运行时代码，再逐文件原子替换，调用包内离线安装器；保留规则、站点配置（含已有 `endpoint_limits` 和 `repeat_ban_policy`）、`repeat_bans.json`、黑白名单、接口事件及其他日志和 `data`，不自动启用重复封禁升级。逐文件原子替换不等于整个包具备事务原子性。
5. 查看后台任务结果。成功后关闭并重开插件，核对宝塔 Nginx 配置、插件与安装状态版本 `0.1.9` 和正常业务；若提示未接入，防护仍未接入。不要仅因界面显示完成就认定所有站点验收通过。重复封禁升级须单独确认，访客地域的扫描／定位覆盖须分别核对，配置与验证步骤见 [README](../README.md)。

检查和状态查询都不是安装授权。只有明确确认安装才启动独立后台任务，关闭浏览器不会取消已确认任务；不要重复点击或同时用面板上传其他更新。

## 失败与回退

v0.1.8 会准备专用 `.statistics/total.json` 与数据写入权限，不开放 Lua 程序目录写权限。新快照只在缺失时从旧快照复制；已有新快照不会被旧数据替换。代码回退保留该数据目录和权限准备结果，原权限及摘要在私有 `storage-migration.json` 中，不通过回退代码覆盖用户数据。具体迁移与人工恢复边界见 [升级教程](UPGRADE.md#v018-数据存储迁移)。

更新记录与代码备份保存在插件私有 data/updates 范围。失败时执行器尝试恢复本次受管文件和运行时代码，分别报告安装失败与回退状态；回退失败不能显示为更新成功。不要公开整个目录，可能包含管理路径和旧代码。

v0.1.3 执行的任务保存安装退出码、已确认的新安装阶段以及固定诊断码／资源名称，界面以纯文本显示中文原因。不复制原始命令输出、配置值或任意路径；旧更新器执行本次升级时不具备新增诊断字段，应另查最新 `install-status.json`。旧更新器完成升级后，新界面仅在状态身份、版本与时间都匹配时补充安装状态，不拿旧记录冒充本次结果。

检测到同期人工修改时，不会强行覆盖这些变更；恢复冲突会显示失败并阻止再次启动更新，需要管理员先核对文件与备份。请勿删除任务记录来绕过未完成恢复的保护。

自动回退不恢复全部 Nginx 内存状态、应用数据或无关同期变更，也不能代替独立备份。进程被系统终止、断电、磁盘损坏等情况下需要核对任务记录并人工恢复。仅使用宝塔 Nginx 检查和平滑重载，不重启面板或调用系统 Nginx；重载信号成功仍需核实业务。
