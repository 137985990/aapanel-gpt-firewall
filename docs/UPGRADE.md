# 既有 free_waf 5.0 的升级与恢复

本教程用于 **aapanel GPT Firewall v0.1.7** 社区兼容升级。只操作已经安装且运行数据完整的 aaPanel `free_waf 5.0` 或本社区版本，不支持空机器首次安装。请先在测试环境完成恢复和升级演练。

v0.1.1 至 v0.1.6 用户可使用已有 [更新管理](UPDATES.md) 确认升级到 v0.1.7，也可按本教程离线导入。新版入口是“维护工具 → 插件更新”。旧 v0.1 没有更新入口，需手动上传 v0.1.7；不要求先安装 v0.1.1，也不能靠没有安装的更新器自动升级自身。不要使用旧插件商店的更新覆盖社区版本。

v0.1.7 保持 v0.1.1 的 21 个受管文件集合与 `free_waf` 身份不变，不需要放宽旧更新器白名单。接口策略默认不启用：原站点缺少 `endpoint_limits` 时保持原行为，新建规则默认停用且动作为 `observe`。新增重复封禁升级也默认停用，缺少 `repeat_ban_policy` 等同于未启用。升级不自动改写原阈值、规则或白名单，不自动创建或启用这两个可选策略。

重复封禁配置入口为“防护配置 → 重复封禁升级”，选站点后才读取，不在首屏或后台持续查询。默认 `enabled=false`，滚动 24 小时内独立自动封禁达到 5 次对应 7 天、10 次对应 30 天；支持 1 至 8 档，窗口为 60 至 604800 秒、次数为 2 至 1000、时长为 60 至 31536000 秒的整数，各档次数与时长须严格递增。完整字段见 [README](../README.md#v017-重复封禁升级)。这些是默认预设，不代表升级后已生效。

顶部“配置已开启”只表示配置开关，不代表 WAF 正在执行。“核验接入”由管理员手动触发，不写入或重载；既有非受管入口仅有配置证据，本版受管入口还会尝试验证本机 Lua 执行。两者均不能代替全部站点的业务验收。缺少接入时可另行使用“维护工具 → 诊断工具 → 一键修复”，需确认才修改，详见 [更新管理](UPDATES.md)。

已完整安装但没有 `free_waf.conf` 接入文件、且生效配置未加载本插件时，允许只升级代码，保持未启用，不创建接入配置或重载 Nginx。现有接入文件为空、为符号链接或存在冲突时仍停止；旧运行数据缺失时仍不支持升级。需要启用防护应另行检查兼容性、备份并验收，不通过升级隐式开启。

## 一、确认能否升级

- 确认内部插件名是 `free_waf`，原插件目录 `/www/server/panel/plugin/free_waf`、运行目录 `/www/server/free_waf` 和旧数据完整。
- 记录当前面板、Nginx、Lua 与 Python 版本、启用站点、必要模块和原有配置引用关系。缺少模块、库、规则或运行数据时应停止，不运行旧安装器补齐。
- 确认这不是付费 WAF，也不是中文 8.x。若有其他防火墙或重复的 Lua 集成，先停止本次升级并单独确认兼容性。本包不会自动禁用其他插件。
- 本预发布尚未验收未经修改的原生 5.0 还原环境。插件内已有扫描器 `rule.json`，运行目录内的 `header`、`user_agent_white` 等规则文件也是预检条件；旧版本号相同并不等于可直接升级。缺少时停止，不创建空规则绕过检查。
- 保留独立的服务器管理通道与回退窗口。升级期间暂停后台规则编辑、批量站点变更等管理操作，避免与安装交错写入。

ZIP 中仍使用 `free_waf` 插件名和兼容目录；这是原位升级，不是并排安装第二个插件。不要改 ZIP 内的目录、类名或插件标识来强行导入。

## 二、上传之前备份

**必须先备份，再向面板上传。** 面板导入可能在运行安装钩子前覆盖后端等插件文件，钩子自己的备份无法补回这一步之前的旧版本。

至少保留以下内容，放在只有管理员可读的位置，不提交到公开仓库或问题区：

| 内容 | 默认位置与注意事项 |
| --- | --- |
| 旧插件完整目录 | `/www/server/panel/plugin/free_waf`，包括旧后端、页面、元数据、脚本及附带文件 |
| 旧运行完整目录 | `/www/server/free_waf`，包括 Lua、配置、规则、黑白名单、站点配置及目录内日志 |
| 重复封禁策略与长封禁 | `/www/server/free_waf/site.json` 中的 `repeat_ban_policy` 和存在的 `/www/server/free_waf/repeat_bans.json`；随运行目录备份，后者独立于全局黑名单 |
| 宝塔 Nginx 配置 | `/www/server/nginx/conf`，保留主配置与相关引用文件 |
| 面板站点与包含文件 | `/www/server/panel/vhost/nginx`，并检查其引用的其他目录和自定义文件 |
| 外置数据与依赖 | 另设日志目录、自定义规则、符号链接目标及配置引用的其他文件，需要另行盘点与备份 |

`site.json` 中已有的 `endpoint_limits` 和 `repeat_ban_policy` 属于站点配置，应随运行目录备份；存在的 `repeat_bans.json` 是持久升级长封禁记录，不能只备份全局黑名单而遗漏它。接口事件位于实际 WAF 日志目录的 `endpoint_YYYY-MM-DD.jsonl`，若日志在运行目录之外须另行备份。事件与长封禁记录含 IP 与路径，不公开上传。不要因“仅更新代码”省略数据备份。

重复封禁的滚动历史仅在 Nginx 共享内存中，不在 `repeat_bans.json` 内，目录备份不能保存它。平滑重载（smooth reload）可保留仍有效的历史；完全重启（full restart）后历史不恢复，计数压力、内存驱逐、写入失败或锁竞争也可能少计，不从访问日志补算。

此可选功能仅在 Linux x86_64/AArch64 的 LuaJIT FFI 与本地文件锁可用时支持，不新增包依赖；FFI 不可用或锁失败时功能降级，不联网补装，其他环境保持原有防护，不保证重复封禁升级。共享内存修订提示不保证快照即时同步；缺少修订提示时，解封结果跨 worker 最长需 10 秒可见，应稍后手动核对。

以下仅是默认目录的备份示例，不执行安装、卸载或重载；不适合缺少旧运行目录的机器：

```sh
set -eu
test -d /www/server/panel/plugin/free_waf
test -d /www/server/free_waf
test -d /www/server/panel/vhost/nginx
test -x /www/server/nginx/sbin/nginx
/www/server/nginx/sbin/nginx -t

umask 077
backup="/root/gpt-firewall-backups/$(date +%Y%m%d-%H%M%S)"
mkdir -p /root/gpt-firewall-backups
mkdir "$backup"
tar -czpf "$backup/plugin.tgz" -C /www/server/panel/plugin free_waf
tar -czpf "$backup/runtime.tgz" -C /www/server free_waf
tar -czpf "$backup/nginx-config.tgz" -C / www/server/nginx/conf www/server/panel/vhost/nginx
printf '%s\n' "$backup"
```

确认备份可读、空间充足，并另行备份符号链接指向的外部文件；示例不会自动追踪所有外部依赖。若同名备份目录已经存在，示例会停止而不覆盖原备份。保留面板和 Nginx 的当前健康记录。持续写入的日志与临时封禁不是事务性快照，目录备份也不包含全部 Nginx 共享内存状态。

若升级前宝塔 Nginx 配置检查已经失败，先解决原有问题，不能把升级当成修复任意旧环境的手段。

## 三、通过面板上传 ZIP

1. 使用明确标注为 v0.1.7、针对既有 `free_waf 5.0` 或社区版本的 `aapanel-gpt-firewall-0.1.7-upgrade.zip` 前，确认发布记录并核对提供的校验值。没有验收记录的源码压缩包不要当成可直接安装包。
2. 在 aaPanel 第三方插件的 ZIP 上传／导入入口选择升级包。不同面板版本入口名称可能不同，不通过卸载旧插件来获得入口。
3. 由面板解压并执行包内安装钩子，完整保留安装输出。不要同时升级 Nginx、替换其他 WAF 或修改规则。
4. 检查 `/www/server/panel/plugin/free_waf/install-status.json`，确认记录属于本次尝试，而不是上次残留。保存前后的修改时间及安装输出，具体字段以该发布包的实际记录为准。

安装器应使用包内文件，不抓取上游安装器或规则，不覆盖原有规则、站点配置（含 `repeat_ban_policy`）、`repeat_bans.json`、黑白名单和日志，不自动启用升级封禁；依赖不足时停止。实际长封禁快照是运行数据，不是这 21 个受管代码文件之一。离线约定只约束本安装器，面板上传处理及原有界面的网络行为不在此保证内。

总览截图随升级 ZIP 提供，接口策略与网站统计的画廊图片仅随公开源码提供，不属于这 21 个受管文件。安装目录中的 README 无法显示源码画廊时，可查看在线仓库 README；不要为补图修改更新器白名单。

**不要执行旧版卸载脚本，不要先卸载再导入，也不要运行从旧论坛帖子取得的安装命令。** 它们不是本兼容升级的恢复步骤，可能改写或删除现有数据。

## 四、检查状态与业务

状态记录至少需要能说明本次是否成功、宝塔 Nginx 配置检查结果、是否尝试启用以及失败后的回退结果。若记录缺失、时间不符、显示失败或只表明部分回退，请按失败处理；面板弹出成功提示不能替代这些核对。

本版状态约定中的重点字段：

| 字段 | 核对方式 |
| --- | --- |
| `status` | `success` 表示安装钩子报告成功；`failed` 需要排查，不继续扩展上线 |
| `version`、`plugin_name` | 应对应本次项目版本 `0.1.7` 和兼容插件名 `free_waf` |
| `diagnostic_code`、`diagnostic_resource` | 失败预检的固定诊断码和允许公开的资源名称；不包含原始命令输出或配置值 |
| `waf_active` | `false` 不等于防火墙已经启用；即使代码升级成功，仍需核查原有集成和业务状态 |
| `runtime_changed` | 表示本次是否替换运行时代码，不代表所有防护状态已经验证 |
| `plugin_rollback_available` | `false` 提醒钩子无法恢复导入前的插件文件，需要上传前的独立备份 |
| `rollback` | `restored` 只表示所管理范围已恢复；`restore_reload_failed` 表示恢复后的重载仍失败，不能当作完整回退成功 |

`status`、代码回退和业务恢复是不同层面的结果。即使 `rollback` 表示恢复，也不能据此忽略仍为失败的安装状态。

1. 用实际宝塔二进制检查配置，不用系统路径中可能存在的另一个 Nginx：

```sh
/www/server/nginx/sbin/nginx -t
```

2. 确认 Nginx 实际运行、站点可访问，面板能打开插件且没有后端报错；必要时按面板实际机制刷新插件加载，不把重启服务当成默认排错步骤。
3. 检查原规则、站点开关、例外与黑白名单仍存在，日志持续写入。使用备份或升级前的私下记录核对，勿把这些内容贴到公开问题中。
4. 在测试站点和隔离夹具中验证注册封禁能够列出、正确解除且后续请求恢复；验证全局停用规则后，站点例外仍指向目标规则，不误停其他规则。
5. 回归测试站点的正常登录、注册、接口、上传及使用中的流式响应等业务。旧 CC 现在按站点和不含查询串的规范化路径计数，查询串变化不再获得新计数；原阈值仍保留，需验证正常重试与共享出口业务。先观察有限范围，再逐站点验证；不要向生产站点发送攻击载荷来代替隔离回归。
6. 如需可选接口防护，在测试站点明确选择站点、保存启用 `observe` 后核对采样证据，再决定是否采用 `reject` 或 `ban`。现有显式白名单优先；原始限域封禁最长 28800 秒，不写入持久全局 IP 黑名单。未单独启用重复封禁升级时，确认 429 与 `Retry-After` 及其他路径／站点不受该规则影响，详细字段见 [README](../README.md)。
7. 如需重复封禁升级，另行在“防护配置 → 重复封禁升级”选站点，确认共享 NAT／代理误封风险、IP 白名单优先及本站点整站影响后再启用保存。仅独立且成功建立的自动封禁计数，普通命中、人工封禁、观察／仅拒绝、封禁中访问不计；即使来源是单个接口，升级也扩至本站点整站，不跨站点。不要通过反复访问活动封禁来验证累加或自动续期。
8. 在隔离环境验证“解除（保留计数）”使用 `reset_counts:'0'`，提前解封后新的独立自动封禁继续累计有效滚动历史；“解封并清零”使用 `reset_counts:'1'`，两者均需确认，不清除独立人工／基础封禁。原有按 IP 的全局单独解封（`remove_btwaf_drop_ip`／`remove_drop_ip`）跨站移除该 IP 的升级记录，但保留有效滚动历史；全局入口中，只有 `clean_btwaf_drop_ip` 的“全部清理”才重置所有重复封禁历史。默认 7 天自然到期已超出原 24 小时计数窗口，旧次数会过期；10 次档位可能经提前解封、保留历史并在窗口内继续独立违规达到，不由封禁中的重试推进。确认停用后长封禁记录仍保留、但不由本策略执行。

接口事件按站点、IP 和规则，以窗口时长去重后采样；去重窗口从首次记录尝试开始，不等同于请求计数窗口，无法写入会缺失记录，读取也有覆盖上限。“已记录事件”不等于全量请求或全部命中；日志停用或不可写时可能没有记录，不以空白证据页面判断安全。

本教程没有执行上述环境验收或生产验收，也没有给出所有生产站点通过的保证。状态成功但业务异常时，同样应停止扩展上线并检查或回退。

## 五、失败与人工恢复

安装钩子应在宝塔 Nginx 配置检查或启用失败后，尝试恢复本次替换的运行时代码并记录结果。它不能保证恢复上传前已被面板覆盖的后端、页面和元数据，也不能恢复任意时刻的内存封禁状态。

1. 停止重复上传与并发配置变更，保留本次状态记录和脱敏错误信息。不要卸载插件，不自动停用其他防护。
2. 从上传前的插件备份恢复本次覆盖的代码、页面、元数据和随包文件。按文件清单操作，不盲目解压全部备份覆盖当前数据。
3. 核对运行时代码是否已经回退。若没有，仅恢复本次替换的代码；不要用旧运行目录整包覆盖现有配置、规则、黑白名单或日志，也不自动恢复旧 `site.json` 或 `repeat_bans.json`。
4. 只有确认本次修改了某个 Nginx 引用文件且需要恢复时，才从备份取回该文件；不要回滚无关站点和同期合法变更。
5. 再次运行 `/www/server/nginx/sbin/nginx -t`。只有配置检查通过，才考虑通过面板实际机制平滑重载；检查失败时不要重启或重载来碰运气。
6. 重新检查面板、测试站点、日志和封禁状态。若回退仍失败，保留可用服务与独立管理通道，停止自动操作并请求人工排查。

数据备份用于核对和有针对性的恢复，不是自动回滚时恢复旧黑名单、复活过期封禁或抹去升级期间日志的理由。遇到确需恢复数据的情况，应先逐项确认时间范围和后果。

`repeat_bans.json` 中的持久长封禁与内存历史是两类状态：保留该文件不能恢复完全重启前的计数，恢复旧代码也不能重建历史。回退到尚不识别 `repeat_ban_policy` 的旧版本时，即使保留策略和长封禁文件，旧代码也可能不执行升级封禁；应在测试环境核对原有基础防护和业务，不将“数据仍在”当作新功能继续生效的证据。

## 六、反馈与剩余风险

本插件全部 `site.json` 读改写入口共用配置锁，但不约束外部 root／其他程序，也不为 Lua 的其他数据提供跨语言事务。其他 JSON 并发写入、正文解析覆盖和 CDN 信任配置仍需要单独评估。接口策略在共享内存不足等状态写入失败时可能放行，不是应用鉴权或账户额度的替代。本版停用远端 `cnlist` 同步，不会替现有地域名单持续更新；本地 PHP 巡检受站点根目录与扫描限额约束，不证明全站安全。

旧算术／内联 JavaScript `security_verification` 已移除，改为不反射请求 URI、也不创建验证绕过的通用 429 JSON 与 `Retry-After`；依赖旧人机挑战页面的客户端需要在测试环境验证重试处理。定点修复不意味着路线图全部完成，也不保证所有面板与全部站点适配。

通过本仓库 GitHub Issues 提交问题时，提供版本、可复现步骤及脱敏后的状态摘要即可。敏感证据先请求私下安全沟通渠道；不要公开生产地址、账号、密钥、原始请求或完整日志。
