# 已识别 free_waf 的升级与恢复

**适用版本：v0.1.11，实验性兼容预发布。** 使用对应 Release 的升级 ZIP 并核对 `SHA256SUMS`；v0.1.10 已撤回，不使用撤回附件或源码压缩包代替安装包。

本教程记录 **aapanel GPT Firewall v0.1.11** 的兼容升级流程。国内第三方 `free_waf 8.4` 兼容从 v0.1.9 提供；`8.4` 是原插件版本，实测宝塔面板版本为 `12.0.0`。只接受已核验运行 Lua 指纹且数据完整的国内原版 8.4 或已知社区版；纯 aaPanel 5.0 原始指纹尚未验证，不能笼统视作完整支持。不支持空机器首次安装。

已核验社区版用户在确认目标包仍公开且来源兼容后，可使用已有 [更新管理](UPDATES.md) 确认升级，也可按目标版本教程离线导入。入口是“维护工具 → 插件更新”。旧 v0.1 没有更新入口，需手动上传仍公开且已核验的兼容升级包；不要求先安装 v0.1.1，也不能靠没有安装的更新器自动升级自身。不要使用旧插件商店的更新覆盖社区版本。

v0.1.11 保持 v0.1.1 的 21 个受管文件集合与 `free_waf` 身份不变，不需要放宽旧更新器白名单。接口策略模块从 v0.1.9 已删除，历史 `endpoint_limits` 和接口事件仅保留、不执行。重复封禁升级仍默认停用，缺少 `repeat_ban_policy` 等同于未启用。升级不自动改写原阈值、规则或白名单，不自动创建或启用可选策略。

本版访客地域是现有访问日志的只读统计，不新增运行文件、浏览器埋点、后台依赖或 WAF 策略。使用日志实际记录的客户端地址，CDN／代理后可能只是出口；不推断 XFF，不改可信代理或日志格式。固定本地 MMDB 缺失时降级，不联网补库或安装依赖。只在已有扫描范围与定位预算内统计，不能将部分结果认作整段期间全量数据；功能和口径见 [访客地域说明](../README.md#v018-访客地域统计)。

重复封禁配置入口为“防护配置 → 重复封禁升级”，选站点后才读取，不在首屏或后台持续查询。默认 `enabled=false`，滚动 24 小时内独立自动封禁达到 5 次对应 7 天、10 次对应 30 天；支持 1 至 8 档，窗口为 60 至 604800 秒、次数为 2 至 1000、时长为 60 至 31536000 秒的整数，各档次数与时长须严格递增。完整字段见 [README](../README.md#v017-重复封禁升级)。这些是默认预设，不代表升级后已生效。

v0.1.11 支持同页“批量配置站点”：多选或筛选后全选，明确读取后统一编辑；每次最多 500 个站点。默认保留各站原有启用状态，统一启用／停用须手动选择；每次批量保存均需确认。只覆盖所选站点的窗口和全部阶梯，不合并各站计数，不修改未选站点或清除封禁历史。保存使用同一个站点配置锁与版本校验，一次原子写入、一次经检查的宝塔 Nginx 重载，不循环调用单站点保存。全部校验通过前不写入，失败恢复按整批处理；恢复冲突或网络中断须重读核对，不以部分响应当成功。批量模式不提供跨站解封，查看记录和解封仍在单站点模式。

v0.1.11 另含“当前封禁 → 风险 IP 封禁建议”，只在人工点击后读取所选站点拒绝日志；“全部站点”逐站串行读取，可停止、筛选和分页，汇总不执行封禁。进入本站重新分析并人工确认后，才写入独立的 `manual_site_bans.json`。该快照由面板写入，Nginx 只读；程序目录不能向工作进程开放写入。缺失快照代表尚无此类封禁，不在读取或安装时创建；损坏快照不能当空表重置。备份时包含该文件和其固定锁（如已存在），但代码回退不覆盖此数据。增删后须检查配置、平滑重载并核验执行端；保存不等于生效。旧接入缺少本机健康入口时如实显示执行端未核验，不自动修复接入。基础、全局及重复升级封禁不受此处解除影响。详情见 [风险 IP 封禁建议](../README.md#v0111-风险-ip-封禁建议)。

顶部“配置已开启”只表示配置开关，不代表 WAF 正在执行。“核验接入”由管理员手动触发，不写入或重载；既有非受管入口仅有配置证据，本版受管入口还会尝试验证本机 Lua 执行。两者均不能代替全部站点的业务验收。缺少接入时可另行使用“维护工具 → 诊断工具 → 一键修复”，需确认才修改，详见 [更新管理](UPDATES.md)。

v0.1.11 另外调整增强 CC 请求计数的 IP 隔离、PHP 禁止目录的尾斜杠兼容，以及文件参数／Header 字段的漏检；不包含在历史 v0.1.9 附件中。增强 CC 仅更换请求计数命名空间，不清除已有封禁、历史或改写配置；PHP 目录配置保留原文。`file`、`files`、`img` 将重新接受已启用的 GET／表单规则检查，Header 也不再使用表单字段跳过清单，升级前应在恢复出的测试环境验证正常上传、文章保存和 API 请求。富文本兼容字段、JSON 检测范围和 POST XSS 开关不因此全面改变，具体边界见 [修复说明](../README.md#v0111-的现有问题修复)。

已完整安装但没有 `free_waf.conf` 接入文件、且生效配置未加载本插件时，允许只升级代码，保持未启用，不创建接入配置或重载 Nginx。现有接入文件为空、为符号链接或存在冲突时仍停止；旧运行数据缺失时仍不支持升级。需要启用防护应另行检查兼容性、备份并验收，不通过升级隐式开启。

## 国内 8.4 迁移边界

来源预检严格核对运行 `init.lua` 的 SHA256：已核验原版为 `bt-free-waf-8.4`；已知社区摘要白名单或与已核验升级包候选完全相同的代码为 `known-community`。未知、自定义或付费版本默认以 `source_profile` 拒绝；品牌、注释、版本号及完整配置均不能代替指纹，不能删除守卫放行。纯 aaPanel 5.0 原始指纹尚未核验，先另行核验，不落入泛化的 legacy 分支。

安装器包含已核验社区版本运行代码的精确指纹，避免合法旧版本因清单遗漏被拒绝升级；不按版本号放行未知代码。历史附件的校验逻辑保持其原有范围。

仅对已识别的国内原版执行以下显式迁移；已存在的其他值、规则内容、阈值、名单、模板与日志保留，不恢复已移除的接口策略，不自动启用注册或重复封禁新策略。

| 对象 | 显式迁移 |
| --- | --- |
| `config.json` 的 `url_black` | 缺失时新增 `open=true`，`status` 沿用已有 `get.status`，不硬改成另一响应码；必要 GET 配置本身缺失时拒绝 |
| `compatibility_profile` | 标记为 `bt-free-waf-8.4`；存在其他来源标记时拒绝覆盖 |
| `site_aliases` | 从已核验 `domains.json` 与 `site.json` 建立别名到主站点的映射；别名冲突、覆盖独立站点或站点缺失时拒绝 |
| 各站点 `disable_rule.header` | 缺失时补 `[]`；其余例外仅在序号含义无歧义时保留，不猜测偏移 |
| CDN 取值方向 | 对原已启用 CDN 的站点显式记录 `cdn_header_order`：`cdn_baidu=true` 取首项，否则取末项；保留原头名称和设置，不据此新增可信代理 |
| 缺失规则文件 | 仅 `rule/header.json`、`rule/cookie.json`、`rule/user_agent_white.json` 允许补 `[]`；已存在文件不清空，其他缺失规则不补造 |

**以下情况拒绝迁移：**必要全局／站点字段缺失或类型异常、规则行异常、封禁或例外语义不明，均先人工核对。尤其是单 IP 黑名单缺少明确的正整数到期时间（不定期／永久语义）时，不改成临时封禁；规则例外索引为负、非整数、越界，存在全局停用规则导致原后台与运行时索引含义不同，或多值 GET 与 POST 例外交叉引用不一致时，不猜测转换。已有别名冲突、未知付费来源及其他不兼容资源也不能靠造空配置或改版本绕过。

保留配置值不等于保留原版运行语义：

- GPT 不等价迁移原版 JSON 正文解析、上传内容与大体积／落盘正文检测；保留上传扩展名配置不代表获得同等内容检查。
- 原版蜘蛛 PTR／反向解析验证不作为等价防护迁移；统计中的 UA 分类也不验证真实蜘蛛身份。
- 原版使用 `remote-host` 请求头改变客户端 IP 首尾选择的特例不恢复，该头不是可信身份凭证。国内兼容按记录的 `cdn_header_order` 选值，仍须由管理员核实真实代理出口、头清理方式及可信代理范围。
- 旧算术／内联 JavaScript 挑战不恢复，限流使用通用 429 JSON 与 `Retry-After`，不建立旧 IP 验证绕过。
- 普通命中不自动累加成旧版封禁；CC 使用 GPT 限时策略。原共享内存封禁与日志不是完整可重建的活动封禁快照，不能宣称全部状态等价延续。

**首次原版升级必须暂停写操作并先做独立备份。** 原版管理器与已运行旧进程不遵守 GPT 新锁；关闭编辑页面不能证明已无写入。暂停规则／站点／名单编辑、商城更新、并发安装及接入修复，再核对升级前快照。新增锁不能提供对原版管理器的追溯互斥。

兼容迁移在私有安装备份下保存 `compatibility-migration.json`（migration journal）及原始身份信息。未完成 journal、预检后或激活前的同期变化、失败回退冲突均停止，不自动覆盖新值、不删除 journal／锁来重试；先对照本次记录、独立备份与实际文件，由管理员决定有界恢复。代码回退不是全量数据事务，独立备份不能省略。

商城可能继续显示原插件旧名，或因 `8.4 > 0.1.9` 显示“更新”；这不是本项目的版本比较或授权。不要点击旧商城更新覆盖 GPT，后续使用“维护工具 → 插件更新”的 GPT 更新器。国内兼容从独立的 v0.1.9 提供，不替换历史 v0.1.8 标签、附件或摘要；已有 v0.1.8 用户也可检测到新版本。

站点列表和详情读取不自动补写配置、删除已不在面板数据库的旧站点或清理历史日志；缺失的可选显示默认值仅在内存补齐。新站点在明确保存后才写入配置并刷新国内别名映射，显示字段不保存为策略。这不是自动清理或站点同步服务，日志保留应由管理员另行管理。

## v0.1.8 数据存储迁移

安装器从有效 Nginx 配置确认工作进程用户，将统计写入运行目录的 `.statistics/total.json`。仅当新快照不存在时从旧 `total.json` 复制一次；已有新快照损坏时停止，不用旧快照覆盖。旧文件保留、不由迁移器改写。旧工作进程在重载前仍可能更新旧快照，因此切换窗口不承诺逐次精确统计。

专用统计目录由工作进程拥有，目录 `700`、文件 `600`；黑名单数据文件的所有者改为该工作进程，规则数据目录保留原所有者、组调整为工作进程组并收紧为 `770`。数据内容与防护策略不因此修改，Lua 程序目录权限不放宽。永久锁文件沿用原 inode，不删除重建。权限准备失败时停止，不用宽泛 `777` 修补。

原权限与摘要记录在安装钩子的私有备份 `storage-migration.json`。代码失败回退不会自动删掉新统计目录或恢复数据权限，以免覆盖新请求与并发变更；需要数据回退时先停止并发写入、另行核对新旧快照和原权限记录，不直接套回旧目录。独立备份也应覆盖这两个统计路径。安装成功后确认工作进程可以使用数据锁和原子写入，同时不能写入程序目录。

## Agent 安装升级清单

本节是 AI agent 的执行入口，不是自动运行脚本，也不授予服务器访问或安装权限。源码根目录的 `AGENTS.md` 指向这里；既有更新器的固定文件清单不包含 `AGENTS.md`，因此安装侧直接阅读本节。按下列顺序执行，每一步满足完成条件后再进入下一步。

### 1. 只读识别与选择分支

从本次用户授权确认目标主机、操作范围与目标发布版本，不能默认沿用历史主机或把“检查更新”解释为允许安装。读取当前插件 `info.json` 的 `name`、`versions`，核对运行目录、宝塔 Nginx、既有数据和接入状态；不要为读版本而导入带有启动副作用的面板插件。不要在交付中回显完整配置、进程参数、凭据或原始日志。

| 环境 | Agent 应采取的动作 |
| --- | --- |
| 没有旧插件、运行目录不完整，或缺少必要规则与依赖 | 停止。明确说明当前包不支持空机器首次安装；不创建空配置、空规则或下载旧安装器凑齐资源 |
| 已核验国内原版 8.4 或已知社区指纹 | 按上方矩阵和迁移边界逐项核对；先在恢复出的测试环境验证，再执行明确授权的升级，版本号相同不代表兼容 |
| 纯 aaPanel 5.0 原始指纹尚未核验，或未知／自定义／付费 WAF、其他 8.x、Lua 入口冲突 | 停止，不以完整目录、改版本号或删除来源守卫放行，不自动停用其他防护 |
| 有社区更新入口且升级获授权 | 优先走“维护工具 → 插件更新”，使用固定仓库的发布附件；流程见 [更新管理](UPDATES.md#一键更新流程) |
| 旧版没有更新入口，或服务器无法访问发布来源 | 使用已校验的离线兼容升级 ZIP，按“三、通过面板上传 ZIP”执行，不先卸载 |
| 代码已更新但未接入 Nginx | 如实报告未接入；接入修复是独立操作，需要另行确认影响，不自动开启原有站点规则 |
| 有活动任务、遗留锁、失败回退或 `recovery_required` | 先核对任务、进程与备份，停止重复安装；不删锁或任务记录绕过保护 |

完成条件：已记录实际环境、当前版本、目标版本及其来源，选定兼容路径，确认没有未解决的任务或恢复冲突。目标版本以本次核实的发布记录为准，不把本教程版本或源码目录名当成“最新版”。

本版另须检查运行目录 `.policy-recovery/pending.json` 及私有备份中的兼容迁移 journal。存在未完成恢复时，先停止升级与配置修改并核对私有快照、实际规则和站点例外；不通过删除记录绕过保护。相关目录随运行目录独立备份，不公开。新更新器的生命周期锁只约束新执行器，首次原版管理器不遵守新锁，仍必须暂停并发安装、接入修复和配置编辑。

### 2. 独立备份与升级前基线

执行下文“二、上传之前备份”，**必须在面板上传或在线更新开始之前完成**。在线更新器的受管代码备份与安装钩子备份都不能替代独立备份。覆盖插件目录、运行目录、宝塔 Nginx 与面板站点配置，以及单独盘点的外置数据；保持备份仅管理员可读。

检查备份归档能列出预期文件且可读取，并确认有可用空间、恢复窗口与独立管理通道。暂停并发配置编辑。私下记录原版本、接入证据和已配置站点；对配置、规则、名单等应保留的稳定文件记录摘要，存在时包含 `site.json` 与 `repeat_bans.json`。日志、统计和临时状态可能持续变化，不把这些正常变化判作静态文件被覆盖，也不把备份当事务快照。

使用固定宝塔二进制检查原配置并记录必要的正常业务基线。完成条件：备份已验证、原配置检查通过、抽查业务有升级前结果，且目标与操作范围仍符合用户授权。

### 3. 校验包并执行已授权升级

| --- | --- |

`site.json` 中已有的 `endpoint_limits` 和 `repeat_ban_policy` 属于站点配置，应随运行目录备份；存在的 `repeat_bans.json` 是持久升级长封禁记录，不能只备份全局黑名单而遗漏它。接口事件位于实际 WAF 日志目录的 `endpoint_YYYY-MM-DD.jsonl`，若日志在运行目录之外须另行备份。事件与长封禁记录含 IP 与路径，不公开上传。不要因“仅更新代码”省略数据备份。

重复封禁的滚动历史仅在 Nginx 共享内存中，不在 `repeat_bans.json` 内，目录备份不能保存它。平滑重载（smooth reload）可保留仍有效的历史；完全重启（full restart）后历史不恢复，计数压力、内存驱逐、写入失败或锁竞争也可能少计，不从访问日志补算。

此可选功能仅在 Linux x86_64/AArch64 的 LuaJIT FFI 与本地文件锁可用时支持，不新增包依赖；FFI 不可用或锁失败时功能降级，不联网补装，其他环境保持原有防护，不保证重复封禁升级。共享内存修订提示不保证快照即时同步；缺少修订提示时，解封结果跨 worker 最长需 10 秒可见，应稍后手动核对。

```sh

test -d /www/server/free_waf

test -x /www/server/nginx/sbin/nginx
/www/server/nginx/sbin/nginx -t

tar -czpf "$backup/runtime.tgz" -C /www/server free_waf
tar -czpf "$backup/nginx-config.tgz" -C / www/server/nginx/conf www/server/panel/vhost/nginx
printf '%s\n' "$backup"
```

确认备份可读、空间充足，并另行备份符号链接指向的外部文件；示例不会自动追踪所有外部依赖。若同名备份目录已经存在，示例会停止而不覆盖原备份。保留面板和 Nginx 的当前健康记录。持续写入的日志与临时封禁不是事务性快照，目录备份也不包含全部 Nginx 共享内存状态。

若升级前宝塔 Nginx 配置检查已经失败，先解决原有问题，不能把升级当成修复任意旧环境的手段。

| 字段 | 核对方式 |

9. 如需核验访客地域，重新打开插件，在网站统计选择站点与时间范围并明确进入“访客地域”；核对世界图、国家趋势及独立 IP／请求数／响应体字节切换。分别检查日志扫描和地域定位覆盖提示；缺库、未知和私有地址不应被当作零流量，省／地区 200 项、城市 500 项截断后切换指标不会恢复省略分组。`active_days` 只表示有已处理记录的自然日，不是停留时长或真人活跃度。定位最多 10000 个独立公网 IP／1.5 秒协作预算，不为补齐地域安装依赖、改日志或扩大服务器操作范围。

历史接口事件只是原采样证据，不是全量请求或全部命中，当前源码不再读取展示或续写该模块事件；不以保留文件或空白页面判断当前防护是否生效。

统计继续使用后台缓存，顶层报告 schema 2 新增 geography schema 1，缓存键前缀为 `website-statistics-v3-geography`。旧缓存缺少地域字段时重新生成报告，不删除用户日志或改防护设置。现有截图不覆盖新增地域页面；按需加载的地图资源来自面板本地，缺失时应确认降级说明，不通过外部 CDN 补齐。

验证范围见上方兼容矩阵；其他环境和实际业务需要分别验证。状态成功但业务异常时，应停止后续操作并检查或回退。

## 五、失败与人工恢复

安装钩子应在宝塔 Nginx 配置检查或启用失败后，尝试恢复本次替换的运行时代码并记录结果。它不能保证恢复上传前已被面板覆盖的后端、页面和元数据，也不能恢复任意时刻的内存封禁状态。

1. 停止重复上传与并发配置变更，保留本次状态记录和脱敏错误信息。不要卸载插件，不自动停用其他防护。
2. 从上传前的插件备份恢复本次覆盖的代码、页面、元数据和随包文件。按文件清单操作，不盲目解压全部备份覆盖当前数据。
3. 核对运行时代码是否已经回退。若没有，仅恢复本次替换的代码；不要用旧运行目录整包覆盖现有配置、规则、黑白名单或日志，也不自动恢复旧 `site.json` 或 `repeat_bans.json`。
4. 只有确认本次修改了某个 Nginx 引用文件且需要恢复时，才从备份取回该文件；不要回滚无关站点和同期合法变更。
5. 再次运行 `/www/server/nginx/sbin/nginx -t`。只有配置检查通过，才考虑通过面板实际机制平滑重载；检查失败时不要重启或重载来碰运气。
6. 重新检查面板、测试站点、日志和封禁状态。若回退仍失败，保留可用服务与独立管理通道，停止自动操作并请求人工排查。

数据备份用于核对和有针对性的恢复，不是自动回滚时恢复旧黑名单、复活过期封禁或抹去升级期间日志的理由。遇到确需恢复数据的情况，应先逐项确认时间范围和后果。

`repeat_bans.json` 中的持久长封禁与内存历史是两类状态：保留该文件不能恢复完全重启前的计数，恢复旧代码也不能重建历史。回退到尚不识别 `repeat_ban_policy` 的旧版本时，即使保留策略和长封禁文件，旧代码也可能不执行升级封禁；应在测试环境核对原有基础防护和业务，不将“数据仍在”当作新功能继续生效的证据。

## 六、反馈与剩余风险

本插件站点配置共锁，黑名单与统计分别使用 Python／Lua 共锁，但不约束外部 root／其他程序，也不提供跨文件全局事务。规则恢复未确认会保留私有快照并停止后续修改；持续存储故障仍需人工处理。统计正常约一秒异步落盘，崩溃或断电可能漏计或重复计数。正文解析覆盖和 CDN 信任配置仍需要单独评估，WAF 不能代替应用鉴权或账户额度。本版停用远端 `cnlist` 同步，不会替现有地域名单持续更新；本地 PHP 巡检受站点根目录与扫描限额约束，不证明全站安全。

旧算术／内联 JavaScript `security_verification` 已移除，改为不反射请求 URI、也不创建验证绕过的通用 429 JSON 与 `Retry-After`；依赖旧人机挑战页面的客户端需要在测试环境验证重试处理。定点修复不意味着路线图全部完成，也不保证所有面板与全部站点适配。

通过本仓库 GitHub Issues 提交问题时，提供版本、可复现步骤及脱敏后的状态摘要即可。敏感证据先请求私下安全沟通渠道；不要公开生产地址、账号、密钥、原始请求或完整日志。
