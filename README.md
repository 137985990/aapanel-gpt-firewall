# aapanel GPT Firewall

面向**已经安装并正常运行 aaPanel `free_waf 5.0`** 的非官方社区兼容升级。管理界面使用中文，项目版本为 **v0.1**。

本项目不收费，不需要模型 API 密钥或订阅。首个版本作为预发布提供，请先在测试环境升级。

这不是 aaPanel、宝塔或 OpenAI 的官方产品，也不是付费 WAF 的替代安装包。**不支持在空机器上首次安装，不支持直接覆盖中文 8.x 或付费 WAF。**

## v0.1 做什么

现有管理能力包括：

- 中文全屏管理、总览趋势、攻击来源地图、站点排行及封禁查询。
- 站点开关、IP / URL / UA / Header / Cookie / GET / POST 规则与站点规则例外。
- CC 与注册滥用防护、可选时长的人工封禁、统一精确 IP 解封。
- 拦截日志检索、网站访问统计、规则导入导出及手动安全巡检。
- 统计后台生成和缓存、按需加载、关闭页面时取消请求，不在每次打开时自动运行巡检。

规则和开关以实际安装配置为准，界面存在某个菜单不代表已启用对应防护；地图依赖宿主面板的本地 ECharts / 世界地图资源，地理定位依赖可用的本地数据库，缺少资源时显示降级提示，不自动从公网下载。

本次新增修复：

- 注册防护产生的封禁纳入查询与解除链路，清除该 IP 各注册作用域的封禁和相关计数器，保留其他 IP 的状态。
- 过滤全局停用规则时保留原始位置，使站点例外仍对应目标规则，避免误停其他规则。删除、重排规则后的稳定身份迁移尚未完成。
- 解封时核实持久记录、宝塔 Nginx 检查和重载结果、执行端剩余状态；部分失败不显示成功，允许重试。
- 停用旧版云检测、自动样本上传和误报参数外传；误报按钮不再自动添加全局 URL 白名单。
- 注册与运行时精确封禁支持完整 IPv6 地址识别，避免把带 IPv4 尾部的 IPv6 误认成另一个 IPv4；新注册状态使用无歧义作用域键。

中文管理界面、现有统计与来源标注随兼容升级保留。详细范围见 [更新记录](CHANGELOG.md)。发布包必须通过对应回归与安装验收；这份介绍不替代测试报告，也不表示路线图中的并发存储、完整正文解析、观察模式等工作已经完成。

## 如何升级

请先阅读 [升级与恢复说明](docs/UPGRADE.md)，再操作面板。

1. 确认原插件确实是 aaPanel `free_waf 5.0`，并记录当前面板、Nginx、Lua 和 Python 环境。
2. 在面板上传 ZIP **之前**，备份插件目录、运行目录、宝塔 Nginx 配置及其站点引用文件；另行保护目录外的日志与自定义文件。
3. 先在恢复出的测试环境验证，再通过 aaPanel 的第三方插件 ZIP 上传入口导入兼容升级包，由面板执行包内安装钩子。
4. 检查插件目录中的 `install-status.json` 状态记录，再验证宝塔路径的 Nginx 配置、面板功能和测试站点。

**不要运行旧版卸载脚本，也不要先卸载旧插件再装。** 旧卸载流程可能移除原有运行目录、配置或 Nginx 集成。

下载 Release 中的 `aapanel-gpt-firewall-0.1-upgrade.zip`，不要把 GitHub 自动生成的 Source code 压缩包当作面板安装包。发布包仅含代码和文档，不含原版缺失依赖、初始规则库或任何线上数据。缺少运行资源时安装器会拒绝升级，不会猜测配置或在线补齐。

**预发布兼容范围：**本版尚未完成对未经修改的原生 5.0 环境的恢复安装验收。预检要求已有扫描器 `rule.json`，以及 `header`、`user_agent_white` 等运行规则文件；仅看到旧插件版本号为 5.0，不代表满足所有条件。未通过预检的环境不要自行创建空规则强行继续，需等待独立安装和迁移支持。

### 离线与回滚边界

发布安装器的约定是：使用包内文件，不下载上游安装器或规则，不覆盖现有规则、站点配置、黑白名单和日志；使用 `/www/server/nginx/sbin/nginx` 检查配置，并在检查或启用失败时尝试回退本次替换的运行时代码。

这里的“离线”指安装器不从上游取文件，不代表面板自身完全没有网络活动，也不保证既有界面资源没有外部依赖。缺少旧安装所需的模块、库或配置时，应停止升级，不在线补齐成一次全新安装。

**自动回滚只能覆盖部分阶段。** aaPanel 可能先解压并覆盖后端等插件文件，再调用安装钩子；钩子无法凭空恢复它运行前就被覆盖的旧文件。运行时代码回退成功也不等于整个插件、面板与共享内存状态已完整恢复，上传前的独立备份仍是必要条件。

这些是发布包应满足的安装约定，不是对任意 ZIP 或全部生产环境已经通过验证的承诺。状态记录缺失、失败或含义不明时，不要继续扩展上线。

## 已知限制

- Python 与 Lua 的多进程 JSON 读改写仍有并发覆盖风险，不能视为已经具备跨语言事务保证。
- JSON、上传、较大正文及落盘正文的检查覆盖不完整；兼容性跳过不等于完整 API 防护。
- 启用 CDN 时需要核对可信代理范围和源站访问限制，不能直接信任任意转发头。
- 临时封禁与 Nginx 共享内存状态不等同于文件备份；重载和恢复后的状态需要实际核实。
- 无法唯一还原作用域与地址的旧注册状态不会被猜测删除；影响目标解封时返回失败，需等待原 TTL 到期或按作用域排查。人工 IP 段规则仍使用既有 IPv4 格式，不代表已完成全套 IPv6 防护。
- 包内提供匿名中文响应模板，但安装器不覆盖既有响应模板和定制页面；模板采用与代码升级是两回事。
- 未承诺所有面板、Nginx 版本及全部生产站点兼容，也不承诺零误报、零漏检或抵御所有流量攻击。请逐站点验证正常业务。

## 本地验证

```sh
python tools/check.py
node --test tests/test_attack_charts.js tests/test_frontend_performance.js
python tools/build_release.py --output dist/local
```

Python 测试使用标准库；前端逻辑测试使用 Node.js 内置测试框架。Lua 回归需要 LuaJIT 与 `lua-cjson`，可通过 `FREE_WAF_LUAJIT` 指定可执行文件。安装器测试只使用临时目录和模拟 Nginx，不操作真实运行目录。不存在的运行环境会明确显示跳过，不应解释为已完成该环境验证。

仓库提供 `tools/ci-template.yml` 自动测试模板，默认不执行 GitHub Actions。仓库管理员可核对动作版本和所需权限后，将其放入 `.github/workflows/test.yml` 启用；本次发布不为此扩大账户授权。
